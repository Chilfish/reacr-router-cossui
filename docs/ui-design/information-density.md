# 信息密度与界面冗余

> 页面层规则，补充 [patterns.md §0](./patterns.md#0-信息预算) 的信息预算与 [visual.md §7](./visual.md#7-常见反模式) 的反模式清单。
> 生成界面后按本文删除冗余；与 [writing-style.md](../writing-style.md) 的文案规则同时成立。

## 1. 判断标准

一屏只回答一个问题。写页面前先写一句「谁打开它、想知道什么、下一步做什么」，再决定哪些字段进入界面。不服务这句话的数据留在二级页、详情页或接口里。

三条可检查的约束：

1. **一个事实只出现一次**：同一数字、同一名称、同一状态不在标题、正文、脚注里重复。
2. **一个区块一个焦点**：一个主数字或一句主标题，至多一个动作。
3. **界面不写统计口径**：口径属于数据文档或接口说明，页面只展示结果。

## 2. 四个冗余信号

| 信号                   | 表现                                                                | 处理                               |
| ---------------------- | ------------------------------------------------------------------- | ---------------------------------- |
| 同一事实的重复表述     | 一行 caption 与下方读数展示同样的数字；同一身份用头像加色点各标一次 | 保留信息层级最高的一处，其余删除   |
| 口径脚注               | 区块底部解释统计范围、加权方式、列的含义                            | 口径写进数据文档，界面删除         |
| 自证式导航             | 「查看详情 →」「进入 X 的首页 →」；区块 meta 复述统计范围           | 标题本身可点，一个区块最多一个动作 |
| 因字段存在而存在的区块 | 新面板与已有面板回答同一个问题                                      | 先问这个区块回答什么；重复的删掉   |

一条直接可用的判断：**需要脚注才能说清的数字，先从这一屏删掉。** 脚注通常说明这个数在这一屏没有立足点。

## 3. 生成后的删除清单

AI 生成的页面常见形态是：所有字段同时上屏，每个字段配一行说明，区块底部再补一段口径脚注，最后加几个详情入口。单独看每个组件都合理，合起来是一页没有主次的清单。交付前逐条过：

- [ ] 每个数字只出现一次
- [ ] 每个名称只出现一次；头像或色标已经表达身份时，不再加第二个标记
- [ ] 没有解释统计口径的脚注
- [ ] 没有「详情 →」「进入 X →」这类重复入口
- [ ] 没有与现有区块回答同一问题的新区块
- [ ] 去掉所有 caption 与脚注后，页面仍然成立
- [ ] 区块之间的字号、间距、视觉重量不完全相同，存在一个主视觉
- [ ] 新增的区块能说出它替代了什么，而不是只增加了什么

## 4. 验收方法

- **三秒测试**：三秒内能否说出这一屏是干什么的。
- **眯眼测试**：模糊 5–10px，能否看出一个主视觉。
- **删除测试**：逐个删掉 caption 与脚注，页面是否仍回答核心问题。
- **净增行数**：只加不减的改动需要说明这些新增信息为什么必须同时在场。

前两条与 [research.md §5](./research.md#5-评审方法) 的评审顺序一致，可以在同一轮走查里完成。

## 5. 高密度何时合理

高密度不是缺陷。日志、表格、监控面板、专业工具本来就需要密度，但它们通常满足：

- 使用者是熟悉任务的专家，多次使用后形成肌肉记忆。
- 信息位置稳定，对齐严格，数字等宽、右对齐、单位固定。
- 层级靠位置与字重建立，不靠更多说明文字。

不能把「数据密」当成跳过取舍的理由。高密度来自稳定结构，不来自把所有字段都放上去。页面类型与骨架见 [patterns.md §2](./patterns.md#2-页面类型)。

## 6. 机器视图与人类页面

需要全量字段时另开出口（接口、导出、可读的 `.md` 路由），不复制到人类页面。人类页面只保留当前问题需要的信息，并给一个明确入口。规则见 [patterns.md](./patterns.md) 与 [interaction.md §3](./interaction.md#3-url-与状态)。
