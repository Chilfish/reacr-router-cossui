## 吸收下游项目的调研结论

### 做了什么

- 新增 `docs/ui-design/information-density.md`：一屏一个焦点、四个冗余信号、生成后的删除清单、验收方法。
- `docs/ui-design/patterns.md`：补「记录型表格在 `md` 以下换成堆叠列表」，列表行改为「短文本可截断、标题与正文换行」，新增页面检查清单加入信息密度与响应式表格两项。
- `docs/ui-design/research.md`：补 AI 生成界面堆信息的机制（不确定性下取最大信息量、解释语态漏进界面、缺少页面级注意力预算、从数据模型长页面）与脚注成因；结论地图、正反例库、评审顺序同步更新。
- `docs/ui-design/GENERAL.md`、`visual.md`、`README.md`、`docs/README.md`、`PULL_REQUEST_TEMPLATE.md`、`git-workflow.md`：改为链接 `information-density.md`，不再各自复述同一份冗余清单。
- `AGENTS.md`：从 158 行精简到 79 行。目录树与「意图 → 文件」映射移入 `docs/planning/architecture.md`，完整反模式表保留在 `postmortem/` 与 `code-style.md`。
- `docs/planning/architecture.md`：新增「意图 → 文件」一节与 ADR-006（根指令文件保持短）。
- 全仓库移除 emoji：状态标记改为文字（未开始 / 进行中 / 已完成 / 暂缓 / 已移除），示例代码的勾叉改为「正确 / 错误」，`env.server.ts` 的日志去掉符号，评审模板的评分与严重度标记改为文字。

### 为什么

下游项目在使用本模板时沉淀出几条可执行结论：AI 生成的界面倾向于堆信息并补脚注、根指令文件过长会降低遵循率、记录型表格在窄屏压缩会破坏可读性。这些是通用规则，与具体业务无关，因此落进本模板的规范文档，而不是把下游的调研原文搬过来。

### 判断与取舍

- 不新增 `docs/research/` 层：模板仓库不需要外部资料综述，`ui-design/research.md` 已承担「依据」职责，新结论以可执行规则的形式写进规范即可。
- 未采纳下游的两条内容：`chat-visualization.md` 属于业务特定方案；下游 README 里的成员色体系与 1180px 栅格依赖其业务模型。
- 未写入「表单内按 Enter 先提交当前值」：模板的 `TimeInput` 的 `handleKeyDown` 只处理上下键，该行为在本仓库不成立，按「文档即事实」不记录。
